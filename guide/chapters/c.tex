\section{How To Read The Examples}

Every public function from \cmd{ultimate.h} and \cmd{uci.h} appears below.
Each listing shows one complete operation within a program; calls share state
only when the text says so. The guide build compiles every displayed call form.
Unless a listing shows otherwise, it runs after including \cmd{stdio.h}, \cmd{string.h},
\cmd{ultimate.h} and \cmd{uci.h}. Result-returning calls use this pattern:

\begin{listingbox}
uint8\_t err = ultimate\_init();\
if (err != ULTIMATE\_OK)\
\hspace*{1em}printf("init: \%s\textbackslash n", ultimate\_strerror(err));
\end{listingbox}
The call prints nothing on success. With UCI disabled, it prints:

\begin{outputbox}
INIT: NO ULTIMATE FOUND
\end{outputbox}

An \textsc{Output} box contains only text the listing actually prints on the
C64. A \textsc{Result} box describes a return value, memory change or visible
hardware effect. Captured output below came from an Ultimate 64 Elite; model
names, paths, directory entries, addresses and network replies vary with the
machine and the files or servers used.

The C64 holds text in PETSCII, the PET Standard Code of Information
Interchange. The Ultimate speaks ASCII. The two codes agree on the digits and
on the uppercase letters and disagree on case, and cc65 maps lowercase source
letters to the uppercase byte values the two share. Path, filename and header
literals therefore appear in lowercase source even though the firmware receives
uppercase text.

Zero is success. Appendix~A lists the remaining results. Include
\cmd{ultimate.h} for the service API; include \cmd{uci.h} only for the raw
transport examples at the end of this chapter.

\evidence{\cmd{include/ultimate.h}; \cmd{include/uci.h}}

\section{Start And Discover The Machine}

\begin{listingbox}
int main(void)\
\{\
\hspace*{1em}ultimate\_capabilities caps;\
\hspace*{1em}char text[64];\
\hspace*{1em}uint16\_t length;\
\hspace*{1em}uint8\_t err = ultimate\_init();\
\
\hspace*{1em}if (err != ULTIMATE\_OK || !ultimate\_available()) return 1;\
\hspace*{1em}err = ultimate\_detect(\&caps);\
\hspace*{1em}if (err == ULTIMATE\_OK \&\& ultimate\_has\_http(\&caps))\
\hspace*{2em}puts("http target present");\
\
\hspace*{1em}err = ultimate\_identify(UCI\_TARGET\_DOS1,\
\hspace*{3em}text, sizeof text, \&length);\
\hspace*{1em}if (err == ULTIMATE\_OK) printf("dos: \%s\textbackslash n", text);\
\hspace*{1em}err = ultimate\_identify(UCI\_TARGET\_DOS1,\
\hspace*{3em}text, sizeof text, NULL);\
\
\hspace*{1em}err = ultimate\_get\_model(text, sizeof text, \&length);\
\hspace*{1em}if (err == ULTIMATE\_OK)\
\hspace*{2em}printf("model received: \%u bytes\textbackslash n", length);\
\hspace*{1em}err = ultimate\_get\_model(text, sizeof text, NULL);\
\hspace*{1em}return err != ULTIMATE\_OK;\
\}
\end{listingbox}

\begin{outputbox}
HTTP TARGET PRESENT\\
DOS: ULTIMATE-II DOS V1.2\\
MODEL RECEIVED: 17 BYTES
\end{outputbox}

\cmd{ultimate\_init()} performs the required startup check;
\cmd{ultimate\_available()} reads the resulting SDK state without touching
hardware. \cmd{ultimate\_detect()} fills \cmd{caps}; use the
\cmd{ultimate\_has\_*()} macros to test targets. The paired identify and model
calls show the optional final parameter: pass \cmd{\&length} to receive the
stored string length, or \cmd{NULL} when only the terminated string matters.
The firmware documentation marks the command behind
\cmd{ultimate\_get\_model()} deprecated; the SDK retains this existing wrapper
for compatibility.

\subsection*{Report an error and its raw device code}

\begin{listingbox}
if (err != ULTIMATE\_OK) \{\
\hspace*{1em}printf("\%s (device \%u)\textbackslash n",\
\hspace*{2em}ultimate\_strerror(err), ultimate\_device\_code());\
\}
\end{listingbox}

\begin{resultbox}
The message names the SDK error and includes the last raw device status.
When the target supplied no numeric status, that value is
\cmd{UCI\_DEVICE\_CODE\_NONE} (65535).
\end{resultbox}

\cmd{ultimate\_strerror()} returns stable SDK text.
\cmd{ultimate\_device\_code()} returns the last target-specific numeric status
for diagnostics; do not use that firmware-specific number as application
control flow.

\section{Read SID Addresses Through Deprecated HWINFO}

The SID is the C64's sound chip, the Sound Interface Device. An Ultimate~64
can present more than one of them, and this call reports where each one is
mapped.

\begin{listingbox}
ultimate\_sid\_info info;\
uint8\_t i;\
\
err = ultimate\_legacy\_get\_sid\_info(\&info);\
if (err == ULTIMATE\_ERR\_NOT\_SUPPORTED)\
\hspace*{1em}puts("legacy sid query unavailable");\
else if (err == ULTIMATE\_OK)\
\hspace*{1em}for (i = 0; i < info.count; ++i)\
\hspace*{2em}printf("sid \%u: \$\%04x type \$\%02x\textbackslash n",\
\hspace*{3em}(uint8\_t)(i + 1), info.sid[i].primary\_address,\
\hspace*{3em}info.sid[i].type);
\end{listingbox}

\begin{outputbox}
SID 1: \$D400 TYPE \$83\\
SID 2: \$D400 TYPE \$83\\
SID 3: \$D400 TYPE \$85\\
SID 4: \$D400 TYPE \$85
\end{outputbox}

Firmware without that command instead prints
\cmd{LEGACY SID QUERY UNAVAILABLE}.

Firmware still implements this query, but its documentation marks
\cmd{CTRL\_CMD\_GET\_HWINFO} deprecated and publishes no replacement
C64-side UCI command. The function is therefore named
\cmd{ultimate\_legacy\_get\_sid\_info()}; always handle
\cmd{ULTIMATE\_ERR\_NOT\_SUPPORTED} in case the command is removed.

The call fetches the count and every configured address in one operation. Each
record also has a
\cmd{secondary\_address}; zero means there is no second mapping. The type byte
is retained exactly as the firmware returns it. It distinguishes current SID
implementations and mapping modes, not 6581 from 8580, so do not use it as a
chip model. Check the result before reading the records.

\evidence{\cmd{include/ultimate.h}; \cmd{src/uci/ultimate.s};
\cmd{software/io/command\_interface/control\_target.cc}}

\section{Read And Change The Live Palette}

\begin{listingbox}
uint8\_t palette[ULTIMATE\_PALETTE\_BYTES];\
uint8\_t err;\
\
err = ultimate\_palette\_get(palette);\
if (err == ULTIMATE\_OK) \{\
\hspace*{1em}palette[0] = 0;\
\hspace*{1em}palette[1] = 0;\
\hspace*{1em}palette[2] = 0;\
\hspace*{1em}err = ultimate\_palette\_set(palette);\
\}\
\
err = ultimate\_palette\_set\_color(6, 255, 0, 0);\
err = ultimate\_palette\_reset();
\end{listingbox}

\begin{resultbox}
SET COLOUR 6 TO RED: ULTIMATE_OK\\
RESTORE BUILT-IN PALETTE: ULTIMATE_OK
\end{resultbox}

\cmd{ultimate\_palette\_get()} reads all sixteen RGB triples and
\cmd{ultimate\_palette\_set()} writes all of them. The single-colour call sets
index~6 to red. \cmd{ultimate\_palette\_reset()} restores the built-in palette;
none of these calls writes flash or a palette file.
On firmware without the palette commands, each call returns
\cmd{ULTIMATE\_ERR\_NOT\_SUPPORTED}; test the result before using data from
\cmd{ultimate\_palette\_get()}.

\section{Use Ultimate 64 Turbo Control}

\begin{listingbox}
uint8\_t speed;\
uint8\_t err;\
\
if (ultimate\_turbo\_available()) \{\
\hspace*{1em}speed = ultimate\_turbo\_get();\
\hspace*{1em}err = ultimate\_turbo\_set(U64\_SPEED\_4MHZ);\
\hspace*{1em}err = ultimate\_turbo\_badlines(0);\
\hspace*{1em}err = ultimate\_turbo\_badlines(1);\

\end{listingbox}

\begin{resultbox}
AVAILABLE = 1\\
PREVIOUS SPEED = U64_SPEED_1MHZ\\
SET 4 MHZ, THEN RESTORE SPEED AND BADLINES: ULTIMATE_OK
\end{resultbox}

Every portable speed and the machine-specific maximum use the same call:

\begin{listingbox}

\section{Composite A Software Vsprite}

\cmd{ultimate\_vsprite\_draw()} draws a rectangular image directly into a
standard 40-column C64 bitmap. It is local 6510 code: it works without UCI or
Ultimate hardware.

This example draws a two-byte-wide, eight-line masked image. Image and mask
bytes are column-major: every line of byte column zero comes first, followed
by every line of byte column one.

\begin{listingbox}
static const uint8\_t image[16] = \{\
\hspace*{1em}0x00,0x18,0x3c,0x7e,0x7e,0x3c,0x18,0x00,\
\hspace*{1em}0x00,0x18,0x3c,0x7e,0x7e,0x3c,0x18,0x00\
\};\
static const uint8\_t mask[16] = \{\
\hspace*{1em}0xff,0xe7,0xc3,0x81,0x81,0xc3,0xe7,0xff,\
\hspace*{1em}0xff,0xe7,0xc3,0x81,0x81,0xc3,0xe7,0xff\
\};\
ultimate\_vsprite sprite = \{\
\hspace*{1em}(uint8\_t *)0x6000, image, mask, NULL,\
\hspace*{1em}12, 72, 2, 8, 0, VSPRITE\_F\_MASKED\
\};\
\
err = ultimate\_vsprite\_draw(\&sprite);
\end{listingbox}

\begin{resultbox}
The 16 source bytes are composited at cell column 12, raster line 72.
\end{resultbox}

The bitmap pointer is its 8K base. \cmd{x} is a bitmap byte and screen-cell
column from 0 to 39, not a pixel coordinate; \cmd{y} is a raster line from 0
to 199. Width is measured in bitmap byte columns and height in raster lines.
The SDK does no clipping: the complete rectangle must fit.

\begin{reftable}{p{0.36\linewidth}p{0.18\linewidth}p{0.34\linewidth}}
Flags & Source layout & Operation \\
\midrule
\cmd{0} & column-major image & destination OR source \\
\cmd{VSPRITE\_F\_MASKED} & image and mask &
  (destination AND mask) OR source \\
\cmd{VSPRITE\_F\_COPY} & another C64 bitmap & copy the same rectangle; useful
  for restoring a clean background \\
\cmd{VSPRITE\_F\_COLOR} & column-major image & OR the image and write
  \cmd{color} to screen cells containing a non-zero source byte \\
\end{reftable}

Starting from the descriptor above, these calls exercise the other three
operations:

\begin{listingbox}
sprite.flags = 0;                 /* OR */\
sprite.mask = NULL;\
err = ultimate\_vsprite\_draw(\&sprite);\
\
sprite.flags = VSPRITE\_F\_COPY;  /* restore */\
sprite.source = (uint8\_t *)0x4000;\
err = ultimate\_vsprite\_draw(\&sprite);\
\
sprite.flags = VSPRITE\_F\_COLOR; /* OR and recolor */\
sprite.source = image;\
sprite.screen = (uint8\_t *)0x4400;\
sprite.color = 6;\
err = ultimate\_vsprite\_draw(\&sprite);
\end{listingbox}

\begin{resultbox}
OR adds source bits; COPY restores the same rectangle from another bitmap;
COLOR adds source bits and writes screen value 6 to touched cells. The first
listing demonstrated MASKED.
\end{resultbox}

For color mode, set \cmd{screen} to the 1K screen base. Color mode cannot be
combined with masked or copy mode. Mask and screen may be \cmd{NULL} when
their modes do not use them. A null required pointer, zero size, invalid flag
combination or out-of-bounds rectangle returns
\cmd{ULTIMATE\_ERR\_INVALID\_ARGUMENT}.

The routine patches its own instructions for speed, so it must execute from
RAM and is not re-entrant. Movement, sub-byte image shifting, background
policy, buffering and frame timing belong to the caller; the
\cmd{demos/vsprites} and \cmd{demos/boing} programs show those two different
policies using this same primitive.

\begin{tip}
For moving objects, save or copy the clean background under last frame's
rectangles, restore those rectangles, update every position, then draw the new
frame. Keeping restoration separate prevents old pixels from trailing behind
the objects.
\end{tip}

\cmd{tests/emulator/sdk.suite}; \cmd{demos/vsprites/vsprites.asm};
\cmd{demos/boing/boing.asm}}

\section{Change And Read The Current Directory}

\begin{listingbox}
char path[128];\
uint16\_t length;\
uint8\_t err;\
\
err = ultimate\_chdir("/USB1/GAMES");\
err = ultimate\_getpath(path, sizeof path, \&length);\
err = ultimate\_getpath(path, sizeof path, NULL);
\end{listingbox}

\begin{resultbox}
path = "/USB1/GAMES"\\
length = 11
\end{resultbox}

The change-directory call selects an absolute or relative firmware path. The
paired getpath calls show its optional output: receive the stored length
through \cmd{\&length}, or pass \cmd{NULL} when the terminated path is enough.

\subsection*{Read every directory entry}

\begin{listingbox}
char name[64];\
uint8\_t attrib;\
uint8\_t err = ultimate\_opendir();\
\
while (err == ULTIMATE\_OK) \{\
\hspace*{1em}err = ultimate\_readdir(name, sizeof name, \&attrib);\
\hspace*{1em}if (err == ULTIMATE\_OK) puts(name);\
\}\
if (err == ULTIMATE\_END) err = ULTIMATE\_OK;
\end{listingbox}

\begin{outputbox}
DATA\\
BIG.BIN\\
README.TXT
\end{outputbox}

\cmd{ultimate\_opendir()} starts one live exchange and each
\cmd{ultimate\_readdir()} releases one entry. \cmd{ULTIMATE\_END} is normal.
Issue no unrelated call inside the loop.

When attributes are not needed, pass the documented optional value:

\begin{listingbox}
err = ultimate\_readdir(name, sizeof name, NULL);
\end{listingbox}

\begin{resultbox}
name receives the entry; no attribute byte is stored.
\end{resultbox}

If a program stops the walk before \cmd{ULTIMATE\_END}, call
\cmd{uci\_abort()} before issuing another command.

\subsection*{Make a directory, and return to the configured one}

\begin{listingbox}
err = ultimate\_mkdir("SAVES");\
err = ultimate\_home();
\end{listingbox}

\begin{resultbox}
SAVES is created inside the current directory.
\end{resultbox}

\cmd{ultimate\_mkdir()} creates one directory in the current one.
\cmd{ultimate\_home()} changes to the directory the machine's owner configured
as its home. Firmware that has no configured home returns
\cmd{ULTIMATE\_ERR\_NOT\_SUPPORTED}.

\section{Open, Read And Close A File}

\begin{listingbox}
uint8\_t buf[128];\
uint16\_t got;\
uint8\_t err;\
uint8\_t close\_err;\
\
err = ultimate\_open("README.TXT", DOS\_FA\_READ);\
if (err == ULTIMATE\_OK) \{\
\hspace*{1em}err = ultimate\_seek(0);\
\hspace*{1em}if (err == ULTIMATE\_OK)\
\hspace*{2em}err = ultimate\_read(buf, sizeof buf, \&got);\
\hspace*{1em}close\_err = ultimate\_close();\
\hspace*{1em}if (err == ULTIMATE\_OK) err = close\_err;\
\}
\end{listingbox}

\begin{resultbox}
got = 128\\
err = ULTIMATE_OK
\end{resultbox}

\cmd{ultimate\_open()} establishes the firmware's current file.
\cmd{ultimate\_seek()} selects an absolute position, \cmd{ultimate\_read()}
reads from it, and \cmd{ultimate\_close()} releases the same file. A short read
is end-of-file, not an error; \cmd{got} is the number stored.

The four open bits combine into the common policies below:

\begin{reftable}{p{0.45\linewidth}p{0.47\linewidth}}
Call & Policy \\
\midrule
\cmd{ultimate\_open(name, DOS\_FA\_READ)} & open an existing file for reading \\
\cmd{ultimate\_open(name, DOS\_FA\_WRITE)} & open an existing file for writing without truncating it \\
\cmd{ultimate\_open(name, DOS\_FA\_WRITE | DOS\_FA\_CREATE\_NEW)} & create only when the name does not exist \\
\cmd{ultimate\_open(name, DOS\_FA\_WRITE | DOS\_FA\_CREATE\_ALWAYS)} & create or replace the file \\
\cmd{ultimate\_open(name, DOS\_FA\_READ | DOS\_FA\_WRITE)} & update an existing file and read it back \\
\end{reftable}

The byte-count output is optional:

\begin{listingbox}
err = ultimate\_read(buf, sizeof buf, NULL);
\end{listingbox}

\begin{resultbox}
buf receives bytes and the file advances; the count is discarded.
\end{resultbox}

\subsection*{Create, write and delete a file}

\begin{listingbox}
static const uint8\_t message[] = \{0x4f,0x4b,13\};\
\
err = ultimate\_open("RESULT.TXT",\
\hspace*{2em}DOS\_FA\_CREATE\_ALWAYS | DOS\_FA\_WRITE);\
if (err == ULTIMATE\_OK) \{\
\hspace*{1em}err = ultimate\_write(message, sizeof message);\
\hspace*{1em}close\_err = ultimate\_close();\
\hspace*{1em}if (err == ULTIMATE\_OK) err = close\_err;\
\}\
err = ultimate\_delete("RESULT.TXT");
\end{listingbox}

\begin{resultbox}
RESULT.TXT: WROTE 3 BYTES, CLOSED, DELETED
\end{resultbox}

The open flags create or replace the firmware-side file.
\cmd{ultimate\_write()} appends the specified bytes at its current position;
\cmd{ultimate\_delete()} removes the named file after it is closed.

\section{Ask What A File Is}

\begin{listingbox}
ultimate\_fileinfo info;\
uint16\_t year;\
\
err = ultimate\_stat("README.TXT", \&info);\
if (err == ULTIMATE\_OK) \{\
\hspace*{1em}year = 1980 + (info.date >> 9);\
\hspace*{1em}printf("\%s: \%lu bytes, \%u\textbackslash n",\
\hspace*{2em}info.name, info.size, year);\
\}
\end{listingbox}

\begin{outputbox}
README.TXT: 1024 BYTES, 2026
\end{outputbox}

\cmd{ultimate\_stat()} takes a name in the current directory.
\cmd{ultimate\_fstat()} answers the same question about the file
\cmd{ultimate\_open()} left open, and takes no name:

\begin{listingbox}
err = ultimate\_open("README.TXT", DOS\_FA\_READ);\
if (err == ULTIMATE\_OK) \{\
\hspace*{1em}err = ultimate\_fstat(\&info);\
\hspace*{1em}ultimate\_close();\
\}
\end{listingbox}

\begin{resultbox}
info describes the open file.
\end{resultbox}

The reply has this layout on the wire and is received straight into the
structure:

\begin{reftable}{lp{0.66\linewidth}}
\cmd{size} & length in bytes \\
\cmd{date} & year less 1980 in bits 15--9, month in 8--5, day in 4--0 \\
\cmd{time} & hour in 15--11, minute in 10--5, two-second units in 4--0 \\
\cmd{extension} & three bytes, space padded, with no terminator \\
\cmd{attrib} & the \cmd{DOS\_ATTR\_*} bits, as \cmd{ultimate\_readdir()} reports \\
\cmd{name} & the name, NUL-terminated by the SDK \\
\end{reftable}

\cmd{date} and \cmd{time} are the packed forms used by FAT, the File Allocation
Table filesystem the Ultimate's storage uses, and they are passed through
without conversion. The example above unpacks the year; the other fields come
out the same way, with a shift and a mask.

A reply shorter than the fixed header is \cmd{ULTIMATE\_ERR\_PROTOCOL}, because
a size read out of half of its four bytes would look like a real answer.

\evidence{\cmd{include/ultimate.h}; \cmd{src/uci/dosinfo.s};
\cmd{include/uci\_protocol.h}}

\section{Rename And Copy A File}

\section{Load And Save C64 Memory}

\begin{listingbox}
uint16\_t end;\
\
err = ultimate\_load("GAME.PRG", 0);\
end = ultimate\_last\_end();\

err = ultimate\_load("FONT.PRG", 0xC000);\

\section{Mount A Disk Image}

The Ultimate emulates disk drives, and mounting puts a disk image file into
one of them. The drive is named by the number it answers to on the serial bus,
8 or 9, rather than by a slot. That bus is the IEC bus, after the
International Electrotechnical Commission, and the number is the one a BASIC
program gives in \bas{load"name",8}.

\begin{listingbox}
err = ultimate\_mount(8, "GAMES/PITFALL.D64");\
err = ultimate\_swap(8);\
err = ultimate\_unmount(8);\
\
err = ultimate\_mount(ULTIMATE\_DRIVE\_LAST, "DEMO.D64");
\end{listingbox}

\begin{resultbox}
PITFALL.D64 is mounted in the drive answering as device 8.
\end{resultbox}

The firmware picks the image type from the extension. \cmd{.D64}, \cmd{.D71}
and \cmd{.D81} hold the sectors of a 1541, 1571 and 1581 disk; \cmd{.G64} and
\cmd{.G71} hold the raw track data that a copy-protected disk needs. Any other
extension is refused.

\cmd{ultimate\_swap()} steps to the next image of a multi-image set, the way
the Ultimate's own menu does.

\cmd{ULTIMATE\_DRIVE\_LAST} is zero, and asks for whichever drive was mounted
into last, or drive~A when nothing has been. A program that uses it works
without knowing how its user configured the machine, and
\cmd{ultimate\_drive\_info()} reports the numbers actually in use.

A drive that is switched off does not exist as far as these calls are
concerned; mounting into one returns \cmd{ULTIMATE\_ERR\_DEVICE}. The next
section switches drives on.

\evidence{\cmd{include/ultimate.h}; \cmd{src/uci/disk.s}}

\section{Control The Machine And Its Drives}

\begin{listingbox}
ultimate\_drives drives;\
uint8\_t running;\
uint8\_t i;\
\
err = ultimate\_drive\_info(\&drives);\
if (err == ULTIMATE\_OK)\
\hspace*{1em}for (i = 0; i < drives.count; ++i)\
\hspace*{2em}printf("type \%u device \%u power \%u\textbackslash n",\
\hspace*{3em}drives.drive[i].type, drives.drive[i].device,\
\hspace*{3em}drives.drive[i].power);\
\
err = ultimate\_drive\_enable(ULTIMATE\_DRIVE\_A, 1);\
err = ultimate\_drive\_power(ULTIMATE\_DRIVE\_A, \&running);
\end{listingbox}

\begin{outputbox}
TYPE 0 DEVICE 8 POWER 1\\
TYPE 2 DEVICE 9 POWER 1
\end{outputbox}

\cmd{ultimate\_drive\_info()} fills in every drive the machine has.
\cmd{type} is a \cmd{CTRL\_DRVTYPE\_*} code: 0 for a 1541, 1 for a 1571, 2 for
a 1581, and \cmd{\$0F} for SoftwareIEC. \cmd{device} is the number to give
\cmd{ultimate\_mount()}. \cmd{power} is 1 while the drive is running.

\cmd{ultimate\_drive\_enable()} switches a drive on with a non-zero second
argument and off with zero. \cmd{ultimate\_drive\_power()} reports the same
state through a pointer, which may not be \cmd{NULL}.

\begin{note}
Two numbering schemes meet here. \cmd{ultimate\_drive\_enable()} and
\cmd{ultimate\_drive\_power()} take \cmd{ULTIMATE\_DRIVE\_A} or
\cmd{ULTIMATE\_DRIVE\_B}, which name a physical drive.
\cmd{ultimate\_mount()} takes the device number the drive answers to on the IEC
bus. \cmd{ultimate\_drive\_info()} connects the two: each record carries both.
\end{note}

\section{Read And Set The Clock}

The Ultimate has a battery-backed clock. It hands the time back as text,
because text is what the firmware formats; nothing in the SDK parses it back
into numbers.

\begin{listingbox}
char now[ULTIMATE\_TIME\_BUFFER];\
uint16\_t length;\
\
err = ultimate\_get\_time(ULTIMATE\_TIME\_PLAIN,\
\hspace*{2em}now, sizeof now, \&length);\
if (err == ULTIMATE\_OK) puts(now);\
\
err = ultimate\_get\_time(ULTIMATE\_TIME\_WEEKDAY,\
\hspace*{2em}now, sizeof now, NULL);\
if (err == ULTIMATE\_OK) puts(now);
\end{listingbox}

\begin{outputbox}
2026/09/04 17:47:45\\
FRI 2026/09/04 17:47:45
\end{outputbox}

\cmd{ULTIMATE\_TIME\_PLAIN} asks for the date and time;
\cmd{ULTIMATE\_TIME\_WEEKDAY} puts the weekday in front of it.
\cmd{ULTIMATE\_TIME\_BUFFER} is a buffer size that fits either form. The final
parameter is optional in the usual way. A buffer too small for the answer
still returns \cmd{ULTIMATE\_OK}, with the part that fitted, as
\cmd{ultimate\_getpath()} does.

\subsection*{Set it}

\begin{listingbox}
err = ultimate\_set\_time(126, 8, 22, 14, 30, 0);
\end{listingbox}

\begin{resultbox}
The clock is set to 2026/08/22 14:30:00.
\end{resultbox}

Setting takes numbers rather than text, in the order year, month, day, hour,
minute, second. The year is the year less 1900, so 2026 is 126. That is the
firmware's own encoding. The other five fields are the numbers they appear to
be.

\section{Move Bytes Through The REU}

\begin{listingbox}
uint16\_t banks;\
\
if (ultimate\_reu\_available()) \{\
\hspace*{1em}banks = ultimate\_reu\_size();\
\hspace*{1em}err = ultimate\_reu\_stash(0x0400, 0, 1000);\
\hspace*{1em}err = ultimate\_reu\_fetch(0x0400, 0, 1000);\
\}
\end{listingbox}

\begin{resultbox}
banks = installed REU size in 64K banks\\
1000 bytes stashed and fetched: ULTIMATE_OK
\end{resultbox}

Availability is separate from size, which is returned in 64K banks. Stash
copies C64 RAM to the REU; fetch copies the same range back. A DMA length of
zero means 65536 bytes.

\begin{tip}
Treat the REU as a fast asset cache, not as ordinary addressable RAM. Load a
level, music bank or animation frames into it once, then fetch only the piece
needed for the current room or frame. It also makes a useful clean-screen or
undo buffer because stash and fetch finish before they return.
\end{tip}

\section{Load And Play PCM Through Ultimate Audio}

Ultimate Audio plays PCM from the REU window in the background; it is not SID
sample playback. Enable \bas{map ultimate audio \$df20--dfff} in the machine's
settings, then probe it before touching a voice.

This example loads a PCM WAV directly from Ultimate storage into REU address
\cmd{\$004000}, configures channel zero and starts it. The PCM bytes never pass
through C64 RAM.

\begin{listingbox}
ultimate\_audio\_voice voice = \{\
\hspace*{1em}0, 0, UA\_VOLUME\_MAX, UA\_PAN\_CENTER,\
\hspace*{1em}0, 0, 0, 0, 1\
\};\
uint8\_t version;\
\
err = ultimate\_audio\_init();\
if (err == ULTIMATE\_OK \&\& ultimate\_audio\_available()) \{\
\hspace*{1em}version = ultimate\_audio\_version();\
\hspace*{1em}err = ultimate\_audio\_load\_wav(\
\hspace*{2em}"/USB0/BOING.WAV", 0x004000UL, \&voice);\
\hspace*{1em}if (err == ULTIMATE\_OK)\
\hspace*{2em}err = ultimate\_audio\_configure(\&voice);\
\hspace*{1em}if (err == ULTIMATE\_OK)\
\hspace*{2em}err = ultimate\_audio\_start(voice.channel, voice.flags);\
\}
\end{listingbox}

\begin{resultbox}
The WAV data is in the REU; channel 0 starts with its file format and rate.
\end{resultbox}

\cmd{ultimate\_audio\_init()} performs an inaudible probe using channel six
and returns \cmd{ULTIMATE\_ERR\_NOT\_SUPPORTED} when the register block is not
mapped. \cmd{ultimate\_audio\_available()} reads the cached result, and the
version call returns the raw module byte only after that result is true.

The WAV loader accepts uncompressed 8- or 16-bit PCM, mono or stereo, from 96
through 65,535Hz. It fills \cmd{reu\_address}, \cmd{length}, \cmd{rate} and the
format bits in \cmd{flags}; channel, volume, pan and repeat points keep the
values supplied by the caller. An 8-bit WAV is unsigned, so the loader fixes
its sign in place in the REU. Stereo data uses
\cmd{UA\_CTRL\_INTERLEAVE}; the returned voice describes its left channel.

To describe raw PCM without a WAV, fill all fields yourself. Length and rate
must be non-zero, all REU ranges and repeat points must fit in 24 bits, and
\cmd{rate} is the rounded divider
\cmd{6250000 / samples\_per\_second}. Use \cmd{UA\_CTRL\_16BIT} for signed
little-endian 16-bit data, \cmd{UA\_CTRL\_REPEAT} with
\cmd{repeat\_a < repeat\_b <= length}, and a pan value from
\cmd{UA\_PAN\_LEFT} through \cmd{UA\_PAN\_RIGHT}.

Choose one format before configuring a raw voice:

\begin{listingbox}
voice.flags = 0;                         /* signed 8-bit mono */\
voice.flags = UA\_CTRL\_16BIT;           /* signed 16-bit mono */\
voice.flags = UA\_CTRL\_INTERLEAVE;      /* 8-bit stereo side */\
voice.flags = UA\_CTRL\_16BIT |\
              UA\_CTRL\_INTERLEAVE;      /* 16-bit stereo side */
\end{listingbox}

\begin{resultbox}
For an 8-bit stereo right voice add 1 to the left voice's REU address and
subtract 1 from its length. For 16-bit stereo add and subtract 2 instead.
Configure both voices before starting either one.
\end{resultbox}

Looping, completion interrupts, volume and pan are independent choices:

\begin{listingbox}
voice.flags |= UA\_CTRL\_REPEAT;\
voice.repeat\_a = 4096;\
voice.repeat\_b = voice.length;\
\
voice.flags |= UA\_CTRL\_IRQ;\
voice.volume = UA\_VOLUME\_MAX;          /* 0 is silent */\
voice.pan = UA\_PAN\_LEFT;\
voice.pan = UA\_PAN\_CENTER;\
voice.pan = UA\_PAN\_RIGHT;
\end{listingbox}

\begin{resultbox}
REPEAT loops bytes 4096 through the end; IRQ latches and asserts completion;
volume accepts 0--63 and pan accepts 0--15. The three named pan constants show
the common positions.
\end{resultbox}

Configure validates and writes the voice but leaves its gate closed. It also
stops the channel and waits for the hardware to settle; always call start
after configure. Start and stop are immediate.

\subsection*{Handle end-of-sample status}

\begin{listingbox}
/* After installing an IRQ handler: */\
voice.flags |= UA\_CTRL\_IRQ;\
err = ultimate\_audio\_configure(\&voice);\
if (err == ULTIMATE\_OK)\
\hspace*{1em}err = ultimate\_audio\_start(voice.channel, voice.flags);\
\
/* In that handler: */\
if (ultimate\_audio\_irq\_status() \& (1u << voice.channel))\
\hspace*{1em}err = ultimate\_audio\_irq\_clear(voice.channel);\
\
/* To cancel playback from the main program: */\
err = ultimate\_audio\_stop(voice.channel);
\end{listingbox}

\begin{resultbox}
The bit for channel 0 is cleared after the sample ends; stop cancels playback.
\end{resultbox}

\cmd{UA\_CTRL\_IRQ} asserts the C64 IRQ line when playback ends as well as
latching the channel bit. Install an interrupt handler that clears it, or keep
interrupts disabled while polling. Status returns all seven channel bits;
clear takes one channel number.

\cmd{demos/boing/boing.asm}}

\section{Inspect Network Interfaces}

\begin{listingbox}
uint8\_t count;\

uint8\_t ipconfig[12];\

if (err == ULTIMATE\_OK \&\& count != 0) \{\

\end{listingbox}

\begin{resultbox}
count = number of network interfaces\\
mac = six bytes; ipconfig = twelve bytes
\end{resultbox}

The count call reports available interfaces. The next two calls read the
six-byte MAC address and the twelve-byte IPv4 configuration for interface zero

\subsection*{Change an interface's address}

\begin{listingbox}
err = ultimate\_net\_ipconfig(0, ipconfig);\
if (err == ULTIMATE\_OK) \{\
\hspace*{1em}ipconfig[3] = 60;\

\end{resultbox}

netmask, then four of gateway. Read the block, change the part you want and
write it back.

time a C64 program runs. Neither the firmware nor the SDK checks the address
against anything else on the segment.

\section{Use TCP And UDP Sockets}

TCP, the Transmission Control Protocol, carries an ordered stream over a
connection. UDP, the User Datagram Protocol, sends separate messages with no
connection and no ordering. Both are opened the same way here and both give
back a handle.

\begin{listingbox}
uint8\_t handle;\
uint8\_t buf[128];\
uint16\_t got;\
uint16\_t sent;\
static const uint8\_t message[] = \{0x48,0x49,13\};\
\
err = ultimate\_net\_connect("192.168.1.50", 6502, \&handle);\
if (err == ULTIMATE\_OK) \{\
\hspace*{1em}err = ultimate\_net\_write(handle, message,\
\hspace*{3em}sizeof message, \&sent);\
\hspace*{1em}do \{\
\hspace*{2em}err = ultimate\_net\_read(handle, buf, sizeof buf, \&got);\
\hspace*{1em}\} while (err == ULTIMATE\_OK \&\& got == 0);\
\hspace*{1em}if (err != ULTIMATE\_END)\
\hspace*{2em}ultimate\_net\_close(handle);\
\}\
\
err = ultimate\_net\_udp("192.168.1.51", 6502, \&handle);\
if (err == ULTIMATE\_OK)\
\hspace*{1em}err = ultimate\_net\_close(handle);
\end{listingbox}

\begin{resultbox}
TCP: 3 BYTES SENT; REPLY BYTES RETURNED IN got\\
UDP HANDLE OPENED AND CLOSED
\end{resultbox}

\cmd{ultimate\_net\_connect()} opens TCP; \cmd{ultimate\_net\_udp()} opens
UDP. Both return a handle. Write reports bytes accepted through \cmd{sent}; read
reports bytes stored through \cmd{got}. A successful zero-byte read means
``not yet'', so poll. \cmd{ULTIMATE\_END} means the peer closed and the handle
is already released; call \cmd{ultimate\_net\_close()} only for a handle still
owned by the program.

\evidence{\cmd{include/ultimate.h}; \cmd{src/uci/net.s}}

\section{Fetch A URL In One Call}

\begin{listingbox}
static const char url[] = \{\
\hspace*{1em}0x68,0x74,0x74,0x70,0x3a,0x2f,0x2f,\
\hspace*{1em}0x31,0x39,0x32,0x2e,0x31,0x36,0x38,0x2e,0x31,\
\hspace*{1em}0x2e,0x35,0x30,0x2f,0\
\};\
uint8\_t reply[512];\
uint16\_t got;\
\
err = ultimate\_http\_get(url, reply, sizeof reply, \&got);
\end{listingbox}

\begin{resultbox}
err = ULTIMATE_OK\\
got = HTTP response-body bytes stored in reply
\end{resultbox}

\cmd{ultimate\_http\_get()} creates, exchanges and closes one GET request.
The explicit bytes prevent cc65 from changing lowercase URL characters to the
C64 character set. \cmd{got} is the body bytes retained; a larger body returns
\cmd{ULTIMATE\_ERR\_TRUNCATED} and has no continuation.

\section{Build A Multi-step HTTP Request}

Opening the request yourself is what adding a header needs. This example
reuses \cmd{url}, \cmd{reply} and \cmd{got} from the preceding one.

\begin{listingbox}
uint8\_t request;\
uint8\_t close\_err;\
static const char header[] = \{\
\hspace*{1em}0x61,0x63,0x63,0x65,0x70,0x74,0x3a,0x20,\
\hspace*{1em}0x74,0x65,0x78,0x74,0x2f,0x70,0x6c,0x61,0x69,0x6e,0\
\};\
\
err = ultimate\_http\_open(HTTP\_VERB\_GET, url, \&request);\
if (err == ULTIMATE\_OK) \{\
\hspace*{1em}err = ultimate\_http\_header(request, header);\
\hspace*{1em}if (err == ULTIMATE\_OK)\
\hspace*{2em}err = ultimate\_http\_exchange(request, HTTP\_BODY\_NONE,\
\hspace*{3em}reply, sizeof reply, \&got);\
\hspace*{1em}close\_err = ultimate\_http\_close(request);\
\hspace*{1em}if (err == ULTIMATE\_OK) err = close\_err;\
\}\
\
err = ultimate\_http\_free\_all();
\end{listingbox}

\begin{resultbox}
GET WITH ONE HEADER: RESPONSE STORED\\
ALL HTTP OBJECTS FREED
\end{resultbox}

\cmd{ultimate\_http\_open()} returns the request handle that header, exchange
and close all use. \cmd{HTTP\_VERB\_GET} is one of the \cmd{HTTP\_VERB\_*}
codes; \cmd{HTTP\_VERB\_POST}, \cmd{HTTP\_VERB\_PUT} and the rest are in
\cmd{uci\_protocol.h}. The header line is one string in \cmd{key: value} form.

Every supported HTTP method is selected at open time:

\begin{listingbox}
static const uint8\_t verbs[] = \{\
\hspace*{1em}HTTP\_VERB\_GET, HTTP\_VERB\_PUT, HTTP\_VERB\_POST,\
\hspace*{1em}HTTP\_VERB\_PATCH, HTTP\_VERB\_DELETE, HTTP\_VERB\_HEAD,\
\hspace*{1em}HTTP\_VERB\_OPTIONS, HTTP\_VERB\_CONNECT, HTTP\_VERB\_TRACE\
\};\
uint8\_t i;\
\
for (i = 0; i < sizeof verbs; ++i) \{\
\hspace*{1em}err = ultimate\_http\_open(verbs[i], url, \&request);\
\hspace*{1em}if (err == ULTIMATE\_OK) ultimate\_http\_close(request);\
\}
\end{listingbox}

\begin{resultbox}
Each iteration creates and closes a request with that method. Opening alone
sends nothing to the server.
\end{resultbox}

This request sends no body, so the exchange is given
\cmd{HTTP\_BODY\_NONE}. The next section builds a body and passes its handle
there instead.

Close every handle you open. \cmd{ultimate\_http\_free\_all()} recovers slots
that an earlier program abandoned.

\evidence{\cmd{include/ultimate.h}; \cmd{src/uci/http.s}}

\Needspace{30\baselineskip}
\section{Build A Request Body}

A POST or a PUT needs a body. The body is built inside the Ultimate rather than
in C64 memory: create a slot, add one field at a time, then give its handle to
\cmd{ultimate\_http\_exchange()}. Only one key and one value are in C64 memory
at any moment, which is what lets a 38K machine post an object larger than it
could hold.

\begin{reftable}{lp{0.54\linewidth}}
\cmd{HTTP\_BODY\_JSON\_OBJECT} & a JSON object \\
\cmd{HTTP\_BODY\_JSON\_ARRAY} & a JSON array \\
\cmd{HTTP\_BODY\_URL\_ENCODED} & form encoding, as an HTML form sends it \\
\cmd{HTTP\_BODY\_BINARY} & raw bytes \\
\cmd{HTTP\_BODY\_NONE} & no body; pass this to the exchange \\
\end{reftable}

JSON is JavaScript Object Notation, the text format most web services take.

\begin{listingbox}
/* Explicit bytes, so cc65 does not change their case. */\
static const char k\_name[] = \{0x6e,0x61,0x6d,0x65,0\};\
static const char k\_score[] = \{0x73,0x63,0x6f,0x72,0x65,0\};\
static const char v\_ada[] = \{0x41,0x44,0x41,0\};\
uint8\_t body;\
uint8\_t request;\
\
err = ultimate\_http\_body(HTTP\_BODY\_JSON\_OBJECT, \&body);\
if (err == ULTIMATE\_OK) \{\
\hspace*{1em}err = ultimate\_http\_body\_string(body, k\_name, v\_ada);\
\hspace*{1em}err = ultimate\_http\_body\_int(body, k\_score, 4200);\
\
\hspace*{1em}err = ultimate\_http\_open(HTTP\_VERB\_POST, url, \&request);\
\hspace*{1em}if (err == ULTIMATE\_OK) \{\
\hspace*{2em}err = ultimate\_http\_exchange(request, body,\
\hspace*{3em}reply, sizeof reply, \&got);\
\hspace*{2em}ultimate\_http\_close(request);\
\hspace*{1em}\}\
\hspace*{1em}ultimate\_http\_body\_free(body);\
\}
\end{listingbox}

\begin{resultbox}
POSTED \{"name":"ADA","score":4200\}; the reply is in reply.
\end{resultbox}

Keys and string values go on the wire as given, and cc65 changes the case of a
plain C literal exactly as it does for a URL. Build them as bytes, or fold the
case back at run time.

The remaining root body format choices are short variations:

\begin{listingbox}
err = ultimate\_http\_body(HTTP\_BODY\_JSON\_ARRAY, \&body);\
err = ultimate\_http\_body\_int(body, "", 1);\
err = ultimate\_http\_body\_free(body);\
\
err = ultimate\_http\_body(HTTP\_BODY\_URL\_ENCODED, \&body);\
err = ultimate\_http\_body\_string(body, k\_name, v\_ada);\
err = ultimate\_http\_body\_free(body);
\end{listingbox}

\begin{resultbox}
The first body is \cmd{[1]}; the second is the form field
\cmd{name=ADA}. JSON object and binary bodies are shown above and below;
\cmd{HTTP\_BODY\_NONE} is passed directly to exchange and creates no body.
\end{resultbox}

\subsection*{Add a boolean, and nest a container}

\begin{listingbox}
static const char k\_alive[] = \{0x61,0x6c,0x69,0x76,0x65,0\};\
static const char k\_stats[] = \{0x73,0x74,0x61,0x74,0x73,0\};\
static const char k\_score[] = \{0x73,0x63,0x6f,0x72,0x65,0\};\
static const char k\_lives[] = \{0x6c,0x69,0x76,0x65,0x73,0\};\
static const char k\_runs[] = \{0x72,0x75,0x6e,0x73,0\};\
static const char no\_key[] = \{0\};\
\
err = ultimate\_http\_body(HTTP\_BODY\_JSON\_OBJECT, \&body);\
err = ultimate\_http\_body\_bool(body, k\_alive, 1);\
\
err = ultimate\_http\_body\_object(body, k\_stats);\
err = ultimate\_http\_body\_int(body, k\_score, 4200);\
err = ultimate\_http\_body\_up(body);\
err = ultimate\_http\_body\_int(body, k\_lives, 3);\
\
err = ultimate\_http\_body\_array(body, k\_runs);\
err = ultimate\_http\_body\_int(body, no\_key, 1);\
err = ultimate\_http\_body\_up(body);\
err = ultimate\_http\_body\_free(body);
\end{listingbox}

\begin{resultbox}
\{"alive":true,"stats":\{"score":4200\},"lives":3,"runs":[1]\}
\end{resultbox}

Adding an object or an array enters it. Every key added afterwards goes inside,
until \cmd{ultimate\_http\_body\_up()} steps back out to the parent. Inside an
array the key is ignored, but the pointer must still be valid; pass an empty
string as shown. Any non-zero value is true.

\subsection*{Send raw bytes instead}

\begin{listingbox}
static const uint8\_t block[] = \{1,2,3,4\};\
\
err = ultimate\_http\_body(HTTP\_BODY\_BINARY, \&body);\
err = ultimate\_http\_body\_binary(body, block, sizeof block);\
err = ultimate\_http\_body\_binary(body, block, sizeof block);\
\
err = ultimate\_http\_body\_clear(body);\
err = ultimate\_http\_body\_free(body);
\end{listingbox}

\begin{resultbox}
The body holds eight bytes, then none; the slot is returned.
\end{resultbox}

Successive calls to \cmd{ultimate\_http\_body\_binary()} append.
\cmd{ultimate\_http\_body\_clear()} empties a body and keeps the slot and its
format; \cmd{ultimate\_http\_body\_free()} returns the slot.

A \cmd{HTTP\_BODY\_BINARY} body takes \cmd{ultimate\_http\_body\_binary()} and
nothing else, and the JSON and form formats take everything else. The firmware
answers the wrong combination with \cmd{ULTIMATE\_ERR\_DEVICE}.

A key is copied through a staging buffer, so it is limited to
\cmd{ULTIMATE\_HTTP\_KEY\_MAX} bytes, which is 34. A longer key returns
\cmd{ULTIMATE\_ERR\_INVALID\_ARGUMENT} and never reaches the wire. Values are
not limited by that buffer, and a string value is at most 255 bytes, which is
the firmware's own length byte.

\begin{warning}
The firmware has sixteen slots for the whole machine, and a program that
crashes returns none of them. Free every body and every request you create.
\cmd{ultimate\_http\_free\_all()} takes back headers and bodies together, and is
how a program recovers slots an earlier one abandoned.
\end{warning}

\evidence{\cmd{include/ultimate.h}; \cmd{src/uci/httpbody.s};
\cmd{include/uci\_protocol.h}}

\section{Probe And Configure The Raw Transport}

\begin{listingbox}
uint8\_t present = uci\_signature\_present();\
uint8\_t ident = uci\_ident\_register();\
uint8\_t old\_timeout;\
\
err = uci\_init();\
old\_timeout = uci\_get\_timeout();\

/* run the deliberately unbounded command */\

\end{listingbox}

\begin{resultbox}
present = 1\\
ident = command-interface identification byte\\
abort = ULTIMATE_OK
\end{resultbox}

The signature and identification-register calls are immediate register reads.
\cmd{uci\_init()} performs the functional startup check. Timeout zero means

\section{Execute A Raw Command With And Without Arguments}

\begin{listingbox}
uci\_request req = \{0\};\
uint8\_t reply[64];\
uint8\_t status[16];\
uint8\_t format = 0;\
uint8\_t sub = CTRL\_HWINFO\_MODEL;\
\

\
memset(\&req, 0, sizeof req);\
req.target = UCI\_TARGET\_DOS1;\
req.command = DOS\_CMD\_GET\_TIME;\
req.args = \&format;\
req.arglen = 1;\
req.data = reply;\
req.datamax = sizeof reply;\
err = uci\_exec(\&req);\
\
memset(\&req, 0, sizeof req);\
req.target = UCI\_TARGET\_CONTROL;\
req.command = CTRL\_CMD\_GET\_HWINFO;\
req.data = reply;\
req.datamax = sizeof reply;\
err = uci\_exec(\&req);\
\
req.args = \&sub;\
req.arglen = 1;\
err = uci\_exec(\&req);
\end{listingbox}

\begin{resultbox}
IDENTIFY: reply contains target name\\
GET_TIME: reply contains formatted time\\
GET_HWINFO: reply contains model name
\end{resultbox}

The identify request has no arguments: zero initialization leaves
\cmd{args}, \cmd{payload} and their lengths empty. The time request supplies
its optional format byte. The hardware-info request is sent first without its
optional selector and then with \cmd{CTRL\_HWINFO\_MODEL}; both forms request
the model, which is what an omitted optional argument means on the wire. A
payload is a second independent span; set it only when required.

To discard reply data or status deliberately, leave the corresponding pointer
and capacity zero:

\begin{listingbox}
req.data = NULL;\
req.datamax = 0;\
req.status = NULL;\
req.statusmax = 0;\
err = uci\_exec(\&req);
\end{listingbox}

\begin{resultbox}
req.datalen = 0\\
req.statuslen = 0
\end{resultbox}

\section{Read A Raw Multi-block Reply}

\begin{listingbox}
err = uci\_exec\_first(\&req);\
while (err == ULTIMATE\_OK) \{\
\hspace*{1em}process(req.data, req.datalen);\
\hspace*{1em}if (!uci\_more\_blocks()) break;\
\hspace*{1em}err = uci\_exec\_next(\&req);\
\}
\end{listingbox}

\begin{resultbox}
Each iteration receives one reply block; the loop ends when\\
uci_more_blocks() = 0
\end{resultbox}

The first call submits the request and returns one reply block. The boolean
call reports whether another follows; the next call releases the current block
and receives another. Do not issue an unrelated command inside this loop.

\section{Decode And Inspect Raw Status}

\begin{listingbox}
static const uint8\_t raw[] = \{\
\hspace*{1em}0x34,0x30,0x34,0x20,0x4e,0x4f,0x54,\
\hspace*{1em}0x20,0x46,0x4f,0x55,0x4e,0x44\
\};\
uint8\_t expected;\
uint16\_t device\_code;\
\
expected = uci\_status\_format(UCI\_TARGET\_HTTP);\
err = uci\_decode\_status(UCI\_TARGET\_HTTP, raw, sizeof raw);\
device\_code = uci\_last\_device\_code();
\end{listingbox}

\cmd{uci\_status\_format()} describes the target's expected encoding.
\cmd{uci\_decode\_status()} decodes actual bytes and records their numeric
status; \cmd{uci\_last\_device\_code()} retrieves it. The decoder accepts an
empty status as success, so this is also the form without status bytes:

\begin{listingbox}
err = uci\_decode\_status(UCI\_TARGET\_DOS1, NULL, 0);
\end{listingbox}

\begin{resultbox}
expected = UCI_STATUS_FMT_DECIMAL3\\
err = ULTIMATE_ERR_DEVICE\\
device_code = 404\\
empty DOS status = ULTIMATE_OK
\end{resultbox}
